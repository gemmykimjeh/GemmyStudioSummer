## COMMON MISTAKES TO AVOID

[err-00003] helpful=3 harmful=0 :: Avoid providing descriptive text or summaries when the user explicitly requests a file deliverable. Always ensure the final output includes the generated file.
[err-00006] helpful=2 harmful=0 :: Avoid 'meta-reporting' where the model describes the research process instead of performing it. If the prompt requires a specific file deliverable, the absence of a downloadable file is a failure, regardless of how detailed the textual summary is.
[err-00010] helpful=0 harmful=0 :: Avoid 'lazy generation' where the model provides a textual summary of a document instead of the document itself. If the prompt asks for a specific file format (e.g., .docx, .pdf), the output must be the file generated via code, not a conversational description of what the file would contain.
## PROBLEM-SOLVING HEURISTICS

[ph-00002] helpful=3 harmful=0 :: If the task involves data manipulation (e.g., variance analysis, sampling) and file output, treat the request as a data engineering task. Use Python to load the data, perform calculations, and save the final result as a downloadable artifact.
[ph-00008] helpful=0 harmful=0 :: For hardware procurement tasks, always include direct, verifiable URLs to product pages. If the prompt requires specific technical features (e.g., analog mixer with onboard FX), explicitly list the feature and provide the link to the manufacturer's spec sheet to demonstrate compliance with the requirements.

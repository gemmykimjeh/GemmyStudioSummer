what is harness?

- summary: there are 5 axes of harness in general. context assembly, memory(read and write), control flow, tool interface, and feedback/credit assignment
- harness engineering is optimizing the whole harness. context engineering is part of harness engineering and ACE does this.

Is ACE enough for harness engineering?

- There are almost no constraints or structural issue that will stop us to make a harness engineering settings.
- ACE covers context, memory(both read and write), feedback/credit.
- It doesn’t cover control flow, tool, skill
- We will need new logic for harness except for ACE cover.
- We can force ACE architecture and add control flow, tool, skill on our own. or use ReAct + ACE.

Meta-Harness & AHE constraints

- Meta-Harness edits single python file which has all the harness axes.
- AHE edits 7 python files separated by usage. There is examples of how they edits the code.
- Since it’s code editing, they need offline session for learn something and edit the code.
- How they run: run train set and find some codes that they should edit. They edit and run again and see the score difference. They do these steps several times to optimize the code. After several runs, the codes are frozen and they run test set.
    - In DAIOps perspective, our benchmark set does not have search sets, that means code optimization is non existence. → We cannot use Meta-Harness & AHE as a baseline.
- We picked ACE as our baseline.
